# Bundled Linux native window candidate (#688)

The selected contract is GTK3 + WebKit2GTK 4.1 inside the x86_64 AppImage, including GI in the frozen launcher and the standalone Python used after source handoff. Playwright WebKit remains a separate browser-tool dependency. This candidate is not natively qualified yet.

Build the closure on Ubuntu 22.04 x86_64. `build_linux.sh` installs the locked `linux-desktop` extra into both interpreters; `Ouroboros.spec` collects GI's typelib graph. After freezing, `scripts/bundle_linux_gtk.py` copies the declared Debian package resources and recursive ELF dependencies, package notices, common license texts, WebKit helpers, GIO TLS modules and GStreamer plugins into `_internal/linux-gtk`. Its manifest records package versions, binary/source-package versions, file hashes, host-library exceptions and relocation edits. `_internal` library aliases point to that same closure, preventing PyInstaller from loading a second GLib/WebKit stack. The AppImage packer refuses a payload without the manifest.

AppRun sets the loader path before exec. `desktop_media.prepare_linux_bundle` restores resource paths after PyInstaller's GI hooks and selects GTK even in a KDE session. [WebKit release builds](https://github.com/WebKit/WebKit/blob/8e6f0e6498f75eabe2fd9d46e87d7469ecad25f0/Source/WebKit/Shared/glib/ProcessExecutablePathGLib.cpp) ignore the developer-only `WEBKIT_EXEC_PATH`; bounded `/usr/.../webkit*` and sandbox-helper prefixes are replaced with equal-length `././...` prefixes. Only NUL-delimited compiled path prefixes are changed; offsets and lengths stay fixed. The desktop shell therefore keeps `_internal/linux-gtk` as its cwd, including after the existing source-launcher exec; server processes already choose their repo cwd. CLI dispatch retains the caller's cwd. WebKit's bubblewrap launcher binds `LD_LIBRARY_PATH` entries; keeping the whole `_internal` directory there is necessary to expose the relocated cwd, helpers and data even when its sandbox masks `/tmp`. Bubblewrap canonicalizes bind sources and restores the old cwd only if it remains mapped. These are source-based expectations, not execution proof: the pinned Debian build, proxy launch, plugin loads and namespace permissions must pass native qualification. Missing display/backend still uses the existing browser fallback, bridge and close paths.

The OS supplies the kernel, glibc/loader, X11 or Wayland session, graphics drivers, fonts and trust store. GTK, WebKitGTK, GI, Soup, ICU and TLS libraries are shipped. The first proposed qualification is Ubuntu 22.04 x86_64 with a mapped X11 window on Xvfb/Openbox. It cannot establish physical-GPU, Wayland, Fedora/Astra/RED OS, microphone or broad codec compatibility. No sandbox-disable environment variable is added. Relocated WebKit sandbox paths, driver ABI interactions and payload size need the native result.

## Parent-run bounded experiment

`.github/workflows/linux-appimage-native.yml` is dispatch-only, read-only, secretless and separate from the release graph. The parent must first register the ignored `build/issue688-evidence-r2` evidence (R1 is already registered), then capture this patch in a research branch/commit. Dispatch that exact branch with `candidate_sha` equal to its 40-character HEAD; the workflow checks both checkout and event SHA. The delegate does not push or dispatch.

```bash
gh workflow run linux-appimage-native.yml --ref <research-branch> -f candidate_sha=<exact-sha>
```

The workflow is bounded to 120 minutes (90 build, 18 native). It uses the digest-pinned Ubuntu image and signed apt snapshot in `native-qualification.Dockerfile`; uv 0.12.1 has its own digest, Python/Node/Betterleaks/Claudexor retain repository pins, and `uv.lock` pins Python inputs. Build-system dependencies resolved while compiling sdists are not a bit-reproducible lock: preserve build logs, exported requirements, final package inventory and artifact digest on every run. The normal release-tag guard is untouched. The experiment creates a tagless diagnostic bootstrap seed and uses the production spec, closure builder and AppImage packer; it never publishes, attests, signs, tags or installs the product on the runner.

Build and qualification run under `safe_test` with disposable roots outside Git and no project installation into the dependency environment. The clean desktop container receives only the candidate source and output artifacts, has no installed GTK3/WebKitGTK/GI, no build-library mounts, no host display socket, no external network and runs as a non-root user. Docker's seccomp restriction is relaxed for nested unprivileged WebKit bubblewrap; the container is not privileged and WebKit's sandbox is not disabled. This condition is part of the evidence, not a claim about the default Docker sandbox.

`qualify_linux_appimage.py` starts the actual AppImage, closes Setup without configuring a provider, and requires a mapped Main window, screenshot, genuine JavaScript → `MainApi.shell_info()` roundtrip, bundled GTK/WebKit library maps, live bundled WebKit web/network helpers and a distinct mount namespace for the web process. A saved HTML suffix instruments only the disposable managed page. It then records a comment-only local fixture commit and repeats through production source handoff, checking the standalone Python executable and bridge source identity. This is cold source handoff, not a live update-feed or restart test. No-display and deliberately removed-typelib cases must report browser fallback and stop cleanly. The artifact is not modified for the damaged-backend negative; that case runs a separately extracted copy. All cases use private ports/state and check ordinary close/TERM cleanup; none calls Panic or a model.

Download `issue688-native-<sha>-<attempt>` immediately and register the complete artifact before discarding the run or integrating this candidate. It includes the AppImage and SHA-256, seed/source identities, GTK manifest, matching Debian source archives with hashes, container identities, package lists, raw logs, JUnit, process maps, bridge replies and screenshots. Mechanical green still says `visual_review_pending`: an independent reader must inspect both screenshots for a loaded interface. A missing artifact, timeout, skip, red build or unavailable native runner is incomplete, never native PASS.

The existing release Linux matrix retains its `ubuntu-latest` artifact label but explicitly runs on `ubuntu-22.04` and installs the same GTK build dependencies. Other platform jobs, tags and release topology are unchanged. Unlike this experiment, release apt inputs are not snapshot-pinned. Qualify the actual release seed separately; a green tagless experiment is not release proof.

Binary relocation modifies WebKit; copying copyright files alone is insufficient. [WebKit licensing](https://webkit.org/licensing-webkit/) includes LGPL/BSD components, and the applicable package notices govern each file. Before any distribution, retain and provide matching source archives (including Debian patches/build scripts), the exact relocation script and dated change notice, licenses and the materials needed to rebuild/replace the libraries; satisfy the applicable source-delivery and modification/debugging terms. The diagnostic builder downloads the manifest's source-package versions from the signed snapshot, while the payload carries notices, common licenses, original/modified hashes and the transformation. The distributor must arrange recipient access and independently assess the selected licenses and replacement path. No compliance approval is claimed.
